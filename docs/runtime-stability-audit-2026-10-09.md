# 运行稳定性与内存复核（2026-10-09）

基线：`fa20bf2cff3d598b70b6df692d08069f251bf3ce`。板型：Waveshare ESP32-S3-Touch-LCD-3.49 V2，逻辑 UI 640×172；ESP-IDF 5.5.4，ESP-SR 2.4.5。

本轮检查板级驱动、音频、WakeNet、BLE、Wi-Fi、HA、主任务以及 UI 页面/定时器生命周期；编译全部 40 个项目 C 文件（包括字体/图像资源），链接完整 ELF。第三方 SDK 采用本机现有构建产物，没有修改 SDK。

## 结论与边界

之前把 LVGL、HA 队列/响应和 CPU 音频工作缓冲迁入 PSRAM 的方向合理：LCD/I2S 真正的 DMA 缓冲仍保留内部 RAM，UI 布局、触控映射和正常操作流程无需改变。仅有三次运行采样，不能证明长时间、BLE 扫描或完整语音链路稳定。

本轮以资源生命周期、并发和失败处理为主。未修改 `components/ui/`、`board_config.h`、任务栈大小、音频采样率/通道、唤醒模型或 `sdkconfig.defaults`；AFE 保持已测的 HIGH_PERF 模式。正常路径保持原有界面与交互。未在板上刷入本轮修复，也没有新的板端实测：当前执行环境无法打开 USB 串口，不能把主机测试当成硬件测试。

注意配置可复现性：本机实际 `sdkconfig` 的 `CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL=16384`，Wi-Fi/LwIP PSRAM 分配关闭，Wi-Fi IRAM 优化开启；仓库 defaults 则为 4096、对应 PSRAM 分配开启、IRAM 优化关闭。已有 sdkconfig 不会被 defaults 自动覆盖。本轮验证使用实际配置，不把 defaults 的潜在收益算入实测，也未切换用户现有配置。

## 本轮修复

| 范围 | 确认的问题 | 修复 |
|---|---|---|
| WakeNet | stop 只改标志，AFE/模型不释放；失败/快速重启可能遗留或交叉使用实例 | 启动前检查几何与预分配；检查两个任务创建结果；任务通知保证双任务就绪后启动；原子状态；停止等待生产者/消费者退出后释放 AFE、模型和工作缓冲 |
| WakeNet | 消费者提前退出可能使生产者堵在 AFE 内部环形缓冲；回调停止可能自等待 | 停止期间继续排空；有时限的 fetch；回调只请求停止，由后续外部 stop/start 回收；超时保留仍被使用的实例，避免强制释放 |
| Audio | RX 初始化、codec/interface 创建及 open 失败时泄漏 | 完整回滚输出初始化；麦克风失败清理其接口，保持原有“扬声器可用则继续启动”行为；限制 size_t→int 读取长度；音量设置失败不提前发布成功值 |
| BLE | IDF void 启动助手忽略任务创建失败，可能留下无 host 的栈 | 自行检查同栈大小、同优先级、同 CPU 的 host 任务创建结果并回滚；停止握手后删除明确的任务，再释放协议栈 |
| BLE | 多入口与 deinit 并发；扫描结束覆盖 CONNECTING；连接中再次扫描/连接；过期名称回调 | 统一生命周期串行化；保留连接状态；拒绝重复连接；取消待建立连接；验证名称回调连接句柄；关闭时清理旧 peer 状态 |
| BLE | 每个广播包在锁内打印名称，阻塞 host/状态读取 | 只在名称变化时、锁外记录；扫描结果容量及正常扫描时长不变 |
| BLE | 部分 deinit 失败后继续使用或重复销毁可能无效 | 标为不可用并记录错误，要求重启；不对部分销毁的栈再次 deinit |
| Wi-Fi | 部分初始化资源未回滚；启动失败仍显示 initialized；32 B SSID/64 B PSK 被截断；状态读写不一致 | 回滚事件处理器、驱动、netif；成功启动后发布状态；按合法固定字段长度复制；短临界区保护状态快照 |
| HA | 超长分块响应的 callback 错误可能被 HTTP 层忽略，导致解析截断数据 | 溢出标志锁存到请求结束，明确拒绝整次响应，下一请求重置；原缓冲容量不变 |
| HA | 拉取失败也设置 valid；命令字段静默截断；参数解析/JSON 节点分配失败可能生成错误命令或泄漏 | 成功解析后发布；拒绝超长字段/非法参数对象；失败时清理节点并放弃命令 |
| Board | 初始化失败遗留总线/面板/触控/帧缓冲/定时器；IMU/ADC 局部失败丢失句柄 | 在尚未启动 LVGL worker 的失败路径按依赖顺序清理；删除未使用的重复初始化函数 |
| LCD | DMA 超时后下一帧可能覆盖仍在发送的缓冲，并丢掉晚到完成信号 | 显式保持 DMA 占用状态，等真实完成后才复用；彩条诊断使用相同保护 |
| 诊断 | 内存日志无法确定蓝牙状态 | 每分钟记录 BLE enabled/ready/scanning/connected 与 WakeNet 状态；采集脚本保留这些记录与 BLE 启停日志 |

额外小优化：麦克风诊断工作缓冲 1,024 B 改为 PSRAM，仅在启用该诊断任务时节省内部内存。正常固件未启动此任务，所以不宣称常态新增 1 KiB 收益。核心收益是防止失败/重启累积泄漏。

## BLE 与未来 NUC11 链路

[Espressif IDF 5.5.4 共存文档](https://docs.espressif.com/projects/esp-idf/en/v5.5.4/esp32s3/api-guides/coexist.html)支持 Wi-Fi STA 连接与 BLE 扫描/连接共存，但 ESP32-S3 只有一套 2.4 GHz RF，按时间分配。开启 BLE 会增加控制器/host 内存与无线调度竞争；“支持共存”不是本项目已经通过音频负载测试。

当前配置已启用软件共存，NimBLE 的可外置分配使用 PSRAM；控制器、任务栈、部分控制结构仍需内部内存。当前 BLE 是扫描/连接/配对功能，不是音频传输。NUC11 音频应通过 Wi-Fi 返回，在本板 ES8311 播放；不要把当前 BLE 配对理解成已经支持蓝牙音箱播放。

必须用实测判断 BLE 开启的具体开销，不能从默认 OFF 的启动流程或没有 BLE 标签的旧 JSON 推出。采样应分别覆盖 OFF、ON 空闲、7 秒主动扫描、配对/已连接、再关闭；至少比较每种状态的内部最低余量、最大连续块与是否回收。短扫描可能落在一分钟采样间隔之间，需要结合串口启停日志并重复测试。

未来建议预算（估算，当前尚未实现/未分配）：

| 增量 | 格式与时长 | 建议容量 |
|---|---|---:|
| 预录环形缓冲 | 16 kHz / 单声道 / S16 / 0.5 s | 16,000 B PSRAM |
| 上行待发送缓冲 | 同格式 / 1 s | 32,000 B PSRAM |
| 下行抖动缓冲 | 24 kHz / 单声道 / S16 / 2 s | 96,000 B PSRAM |
| 分帧/转换工作区 | 取决于协议和解码器 | 16–64 KiB PSRAM |
| 网络/播放任务栈和内部控制结构 | 取决于 WS/HTTP、TLS、解码方案 | 先预留约 20–44 KiB 内部 RAM；不包含额外 BLE 开销，也不是库上限 |

PSRAM 容量充足，限制主要是内部连续块、Wi-Fi/BLE 共存和任务时序。不能把现有约 59 KiB 历史最低余量全部用完；TLS、额外 AEC、断线重连峰值还需重新测量。

实施顺序：

1. 保留单一 I2S 采集者，将同一份音频分发给 WakeNet/VAD 与上传缓冲；不要再开第二个读麦克风的任务。诊断读取也不能与 WakeNet 同时启动。
2. 唤醒回调只投递事件，独立网络任务连接/发送；使用固定容量 PSRAM 环形缓冲、超时与背压，不累计整段录音或整个 TTS 文件。
3. NUC11 分块返回音频；保留 24 kHz 共享 I2S 时钟，单声道下行在播放前按当前声道布局转换。格式/采样率改变必须协调 RX/TX。
4. 先完成半双工对话与断线恢复；播放期间误唤醒需门控或后续加入参考通道/AEC。现有 M 单通道配置不等于已具备全双工回声消除。
5. 完成 BLE ON/扫描/已连接的 30 分钟压力测试与 24 小时运行，再决定是否调整 CPU 分工、Wi-Fi 缓冲或 AFE 配置。官方建议无线协议栈合理分核，但不能在当前未测负载下直接宣称改分核一定提升。

## 已完成的验证与剩余限制

- 全部 40 个项目 C 文件：使用本机原始 compile_commands 与实际 sdkconfig 重新编译，替换所有项目组件归档并链接完整 ELF 成功。复用已编译 SDK/managed_components；这不是从零完成的 `idf.py build`，干净 CMake 构建此前受组件管理器进程枚举权限限制。
- `python3 tests/host/run.py`：ASan/UBSan 下测试生产 WakeNet 生命周期源码，包含 5 个分配失败点、2 个任务创建失败点、30 次启停、无输入超时、回调停止/重启、停止超时保留活动资源并随后安全回收。
- `python3 tests/host/http_boundaries.py`：两个生产 HTTP 回调/请求函数测试边界长度、分块溢出、溢出锁存、下次请求重置、无需保存 POST 响应；模拟 HTTP 层忽略 callback 返回值。
- 内存采集解析器检查通过；UI 图标策略检查通过；UI 源码与显示尺寸/引脚配置 diff 为零。
- 剩余编译警告是原有触控 API 弃用提醒与两个 UI 未用动画函数，没有为清警告更换触控 API。
- 编译期内存差异：静态 D/IRAM 增加 552 B（data +16，bss +304，内部 text +232）；Flash 使用增加 5,764 B；不是新的运行时堆测量。为同步和可靠回收接受约 0.54 KiB 内部开销。
- Host mock 不能验证 ESP-SR DSP 内部行为、FreeRTOS 双核时序、射频、实际麦克风/扬声器或屏幕体验。BLE `nimble_port_stop()` 本身在 IDF 内部有无期限等待，本轮消除了任务创建失败造成“无 host 却调用 stop”的已知路径，但不宣称对 SDK/无线异常的所有关闭情形都有硬性 3 秒上限。

上板后先验证：冷启动→所有页面与触控→Hi ESP 多次唤醒→BLE ON/扫描/连接/OFF 循环→HA 操作与 Wi-Fi 断开恢复。记录新的 `RUNTIME state` 与内存日志，确认无持续下降、DMA 超时、read_errors 增长或重启，再接入 NUC11 流式链路。完整语音链路当前尚未实现，不能在本轮宣布端到端稳定性验收通过。
